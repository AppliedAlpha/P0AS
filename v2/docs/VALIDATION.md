브라우저 검증은 `.local/browser-tests/<UUID>/`에 매번 새로운 DB와 키를 생성합니다. 출석과 토큰 전체 삭제 검증은 이 DB에만 적용합니다. 일반 개발 DB `.local/p0as.sqlite`나 원격 DB를 사용하지 않습니다. Windows에서 테스트 서버를 직접 소유·종료하는 래퍼도 별도 검사하여 정상 종료를 확인했습니다.

개인정보 안내는 사용자 제공의 연구실/보유 기간과 미동의 시 수기 출석 요청 조건을 사용합니다. 동의 시각, 동의문 버전, 별도 동의 이력 테이블은 추가하지 않았습니다.

Node 테스트는 요청·스키마·권한 처리를 독립 메모리 DB에서 검증합니다. D1 에뮬레이터에서는 스키마 적용과 빈 초기 상태를 확인했습니다. 원격 D1의 지연·한도·계정 설정, 실제 Access 로그인 및 실사용 부하는 아직 검증하지 않았습니다.

## 원격 결과

**마이그레이션 이름만 읽기 조회.** 2026-10-27에 원격 `d1_migrations`의 이름을 조회해 0001·0002 적용을 확인했습니다. 원격 DB의 업무 데이터 조회·쓰기, 마이그레이션 적용, Cloudflare 설정·직접 배포·100명 부하 검증은 수행하지 않았습니다. GitHub 저장소 반영과 실제 Cloudflare 배포 검증은 별개입니다. 기존 Firebase나 기존 학기 데이터에도 접근하지 않았습니다.

다음 작업은 [OPERATIONS.md](OPERATIONS.md) 순서대로 진행합니다: 로컬 확인 → 계정과 새 DB ID 확인 → 원격 스키마 적용 → Pages/서버 비밀키/관리자 Access 설정 → 새 가상 데이터 등록 → 원격 출석·권한·환경 분리 확인.
